# Coding-session retrospective: Management & Leadership conversion

Date: 2026-10-07

Session: [Assess BRZ archive conversion](codex://threads/01a10d0c-6308-7cd2-8c20-bc1a16142899)

Scope: the main session and all 34 subagent chats referenced by it, including
assessment, wayfinding, prototyping, implementation, verification and delivery.
Findings concern the environment and workflow observed during those sessions.
Recommendations below are proposed changes; saving this report implements none
of them.

The biggest avoidable costs came from late discoveries, incompatible agent
setup and coordination overhead. Independent verification caught real defects
throughout the work. The proposed improvements should make that verification
arrive earlier and require less coordination while preserving its coverage.

## Prioritized findings

### 1. Preserve approved presentation details through implementation and review

**Observed:** The user approved warning panels with orange titles and icons;
production emitted plain blockquotes. The automated oracle expected those
blockquotes, and native/spec review missed the discrepancy. The user's rejection
triggered another repair and release-verification cycle.

**Improve:** Record approved markup, placement and representative screenshots as
explicit acceptance criteria. Assign final acceptance review to someone who did
not author the evidence being reviewed. The spec reviewer in this session had
authored the native acceptance report.

**Evidence:** [Recorded styling failure and review limits](.scratch/management-leadership-implementation/research/final-review.md).

### 2. Fix the incompatible custom verifier role

**Observed:** The verifier searched for a missing
`implement-spec-single-worker` skill and expected guard/snapshot metadata that
the worktree workflow never supplied. It consequently reported unavailable
protocol verification alongside its technical verdict.

**Improve:** Give the worktree workflow a compatible verifier role, and add a
local preflight that validates role references and required inputs before
dispatch.

**Evidence:** The `forgotten_verifier` subagent's initial searches and final
verification report; the current role configuration at
`C:/Users/stefa/.codex/agents/ticket_verifier.toml` still references the missing
skill and requires the guard's snapshot, attempt and baseline metadata.

### 3. Check the new original archive earlier

**Observed:** The first complete matrix repeated nine successful A/B/C
conversions before D refused duplicate absent-TXT declarations. The next matrix
again completed those nine before D exposed diagnostic-label whitespace
differences.

**Improve:** After relevant integrations, run a quick D inspection/conversion
and independent audit first. Turn discovered source shapes into small synthetic
regressions, then run the required complete matrix once the candidate stabilizes.
This changes the order of feedback; the complete acceptance matrix remains
required.

**Evidence:** [Failed matrix history](.scratch/management-leadership-implementation/research/four-archive-preservation.md),
especially the historical m3 refusal and m4 diagnostic alias mismatch.

### 4. Bound native investigation before expanding it

**Observed:** The recovery worker retrieved all 60 remaining notes; every one
was a 67-byte image wrapper referencing an image already in the original
archive. The session then needed several explanations before settling on the
user's actual requirement: routine conversion directly from the original BRZ.

Native acceptance also checked all 47 category contexts and 330 memberships
before the user's sampling request took effect.

**Improve:** Establish what a few representative cases contain, explain the
implications, and expand investigation when uncertainty remains. Use strategic
visual sampling for distinct behaviors and special cases while retaining full
automated preservation coverage.

**Already completed:** Strategic visual sampling is documented as the repository
default. Preserve that improvement rather than adding another equivalent rule.

**Evidence:** [Recovery findings](.scratch/management-leadership-wayfinding/research/native-source-recovery.md),
[native coverage record](.scratch/management-leadership-implementation/research/native-v3-acceptance.md)
and [visual sampling policy](docs/testing.md#visual-sampling-policy).

### 5. Replace conversational bookkeeping with structured handoffs

**Observed:** The coordinator made 109 follow-up calls, 143 messages and 156
waits, and underwent 13 context compactions. Repeated exchanges covered prepared
checks, frozen commits, stable outputs, evidence locations and metadata-only
merges. These counts describe coordination volume; they do not measure wasted
time by themselves.

**Improve:** Use one handoff manifest containing the candidate commit, owned
files, check results, evidence paths and completion state. Dispatch verification
when that manifest is ready. Keep implementation, verification and integration
responsibilities stable instead of repeatedly repurposing agents.

**Evidence:** Main-session tool history and repeated preparation/completion
handoffs in `ticket_coverage_review`, `four_archive_verifier`,
`integration_merger`, `native_vault_reviewer` and `release_documenter`.

### 6. Create a maintained verification runner and wire it into CI

**Observed:** Pytest, Ruff and dependency checks already exist, but there is no
checked-in CI workflow or active pre-commit hook enforcing them. Agents repeatedly
assembled commands and temporary verification scripts manually.

**Improve:** Add one maintained check command with reliable exit handling and
structured results. Run the public synthetic suite and lint checks in Windows
CI, matching the supported runtime. Keep private archives and native application
checks local. Reuse the existing checks rather than introducing equivalent ones.

**Evidence:** [Existing check commands](docs/testing.md), [tool configuration](pyproject.toml)
and the absence of a checked-in `.github` workflow, pre-commit configuration or
active local pre-commit hook at the time of the retrospective.

### 7. Make current guidance easier to distinguish from historical evidence

**Observed:** Root `AGENTS.md` still directs implementation to the v1 index.
README describes v3 as development and says acceptance/review remain pending,
while the implementation index records completion. The index and testing guide
also contain hundreds of lines of accumulated historical receipts.

**Improve:** Provide one current implementation pointer, keep current status in
one place, and move historical receipts behind links. Add mechanical checks for
broken links and inconsistent completion metadata. Keep always-loaded agent
instructions short.

**Evidence:** [Implementation pointer](AGENTS.md), [README](README.md),
[completed implementation index](.scratch/management-leadership-implementation/README.md)
and [testing guidance](docs/testing.md).

### 8. Standardize worktree execution details

**Observed:** Agents encountered temporary-path length refusals, encoding
problems, missing assumed filenames and repeated interpreter/import-path setup.

**Improve:** A small worktree runner should select the integration `.venv`, bind
imports to the selected checkout, set UTF-8, allocate short unique temporary
paths and verify the imported package location. Discover filenames through the
index or filesystem rather than reconstructing them from memory. The underlying
conventions are already documented; tooling would make them automatic.

**Evidence:** [Worktree testing guidance](docs/testing.md),
[workspace conventions](docs/workspace.md) and the independent audit implementer's
recorded temporary-path refusal and successful rerun with a shorter path.

## Additional design tradeoff

The standard-library-only independent oracle required a custom Windows WIC
decoder and strict PNG checks. Independent expectations and corruption detection
are valuable, but future specifications should explicitly weigh that maintenance
cost against allowing a separate established decoder dependency. The original
constraint was accepted scope; reconsidering it is a future design decision.

**Evidence:** [Decoder implementation](tests/local_acceptance/images.py) and
[independent audit ticket](.scratch/management-leadership-implementation/issues/06-independent-audit-tooling.md).

## Recommended starting order

1. Repair the verifier configuration and validate its required inputs.
2. Carry approved prototype details into explicit acceptance checks and
   independent final review.
3. Add an early original-archive check before the expensive full matrix.
4. Introduce maintained execution/check tooling and structured handoffs.

No repository implementation or global configuration was changed as part of
this retrospective. This Markdown file records the findings for follow-up.
