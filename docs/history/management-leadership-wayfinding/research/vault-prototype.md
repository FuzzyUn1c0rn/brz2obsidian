# Representative vault presentation review

Ticket: [Review the agreed behavior in a representative vault prototype](https://github.com/FuzzyUn1c0rn/brz2obsidian/issues/75).
Started: 2026-10-05. Resolved: 2026-10-06. The user selected layout A;
the candidate is independently checked and its principal cases inspected in
native Obsidian.

## Question and scope

Does automatic display of available note images, preservation of present
Markdown, category hierarchy and actionable source diagnostics work clearly in
a native Obsidian vault?

This is a disposable presentation prototype, not a production converter or
complete-archive acceptance run. Its original-source cases read
`brz/Management & Leadership 2026-10-05.brz` directly. The native recovery backup
is not an input or required preparation step. The
[accepted policy](https://github.com/FuzzyUn1c0rn/brz2obsidian/issues/74#user-content-answer) governs the behaviors.

## Candidate cases

- Original absent ordinary note declarations with valid present card images,
  generated visible image sections and brief source-gap notices.
- Original present table/multiple-image, prose and blank note controls,
  alongside clearly marked synthetic controls, to keep generated presentation
  separate from source Markdown.
- Category hierarchy on both sides, including multiple ordinary parents and
  category Parents/Children immediately below the title before Members/Gallery.
- Missing type-note/icon controls with source warnings and neutral appearance,
  plus a present-icon control separating inherited icons from full note images.
- A repair checklist identifying affected included source thoughts, unavailable
  attachment evidence, corresponding vault notes and the generated outcome.

Three linked native review pages compare notice above images, notice below
images and a dedicated Available note images section. They are supporting
review pages, not duplicate imported thoughts or category members. The existing
native Bases/property conventions remain the baseline.

## Artifacts and verification

Disposable code, private selections, source receipts, generated vault and native
review evidence belong under `tmp/ml-wayfinding/prototype/`. Private source
titles, identifiers, URLs, note text and pictures are not published in this
versioned report. The prototype must emit no forgotten content or identifying
diagnostic entries.

Bounded building and independent verification used separate GPT 6.1 Sol agents
at medium effort, as requested by the user. The candidate contains 22 canonical
source items, four synthetic controls and three supporting layout review pages.
It preserves 53 distinct original payloads in 69 physical copies: 16 additional
unchanged images sit beside exact original Notes.md files so their original
relative embeds remain usable. Ten physically present source bodies and six
absent declarations (five ordinary, one type) are represented.

The independent audit passed 711 checks. It checked original bytes and hashes,
the permitted image-destination adaptation without changes to source syntax or
newlines, selected graph/classification joins, scoped exclusion, honest notices,
icon providers, 186 local links, Base view names and diagnostic anchors. One
finding was repaired: a present icon's approved metadata-length discrepancy was
copied correctly but initially lacked its report warning. The report now retains
both lengths and the actual payload hash, separately from absent-icon warnings.
All 23 focused repair checks passed; no current audit findings remain.

Native inspection in Obsidian 1.13.7 confirmed:

- Original card images appear in the three notice layouts and actual imported
  notes with absent source bodies, without live TheBrain or recovered-note input.
- A present two-image body displays both original images. Its source pipe row
  lacks a Markdown table separator: Obsidian displays the images vertically with
  literal pipes. Preserving the supplied syntax does not establish visual parity
  with TheBrain. This observation does not authorize rewriting present bodies.
- The multiple-parent category shows both ordinary parents immediately below
  its title, before Members/Gallery. Following an ordinary parent exposes its
  reciprocal category Children links. Native Bases render the selected members.
- The unavailable-icon category and its member retain neutral appearance in
  Members/Gallery. The member's full owned card remains visible in its note.
  The present-icon comparison renders real inherited icons separately from cards.
- A source-gap link opens the correct repair entry. The report includes the
  input fingerprint, Brain UUID, thought title/UUID, attachment role/path/raw
  state/declared length/physical absence, vault link and visible outcome. Missing
  icon-provider entries distinguish affected included members. Source repair is
  optional and no unverified native TheBrain link is assumed.

Private receipts are `verification/receipt-private.json` and
`verification/focused-recheck-private.json`; the independent summary is
`verification/handoff.md`. Native screenshots and observations are in `ui/`.
The generated review entry point is `vault/Prototype review.md`.

Portable code and run instructions are captured on throwaway branch

These checks substantiate representative presentation only. They do not prove
