# Keep acceptance expected facts independent of converter interpretation

The independent acceptance checker can orchestrate public production workflows
to obtain actual results. Expected source facts come from raw declarations,
exact payloads, and independently authored source rules. In particular the API
checker binds raw Markdown and owner, role, and name facts directly. Reusing
converter DTOs, BRZ flags, archive scope, or production normalization on the
expected side would hide disagreements about interpretation.

Treat deliberately controlled native observations as evidence for their routing
or contract assertions. Use native admission, exact retained graphs and real
publication for claims about physical history or applied bytes. This allows
focused tests to avoid rerunning native work and keeps proof claims tied to the
seam that actually ran.
