# Charge review work and storage over their actual lifetimes

Bound untrusted review construction before building graphs, including attempted
validation branches and the workspace needed to unwind them. A caught exception
can retain input and stack frames, so release that workspace after its handler
exits. Charge returned immutable graph work cumulatively even after a lexical
owner closes, since the caller can retain the graph. Cumulative model work uses
finite work credit while live envelope and semantic allocations keep separate
capacity checks. For legacy integer metadata, reject before decimal conversion
if the lower bound on digit count exceeds the remaining budget. The magnitude
of a nonzero integer is at least two to the power of its bit length minus one.
Since two to the fourth power exceeds ten, dividing bit length minus one by
four and rounding down gives a conservative bound without allocating the
decimal text.

Size replay capacity using distinct retained content bytes. One measured 36 MiB
review reached roughly 294 MiB of peak commit as replay rebuilt its immutable
graph. The few KiB in its compact control envelope could not account for that
work. Keep raw payload in app-owned spools outside the bounded Git control pipe
and avoid attribute or filter transformations on those exact bytes. Reserve
complete reads before starting paired streams, and retain independent readback
when retrying immutable Git writes before their ref has advanced.

See [the bounded Apply and review work](https://github.com/FuzzyUn1c0rn/brz2obsidian/pull/375).
