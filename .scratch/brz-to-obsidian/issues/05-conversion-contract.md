## Question

What should the Python CLI accept, produce, and report so that a one-time migration into a new vault is trustworthy and practical?

Agree the command and options, supported archive boundary, output directory rules, behavior for existing destinations, deterministic naming, attachment handling, and handling of invalid or unresolved references. Decide what happens to export history, deleted records, and source features without an accepted mapping.

Agree which conditions stop conversion, which produce a warning, and how a report accounts for preserved data and omissions. Include platform/runtime and installation expectations, using the supplied export as the first acceptance case and explicitly limiting claims about other exports.

Use [verified home-thought evidence](11-home-thought-evidence.md) and the accepted trial presentation to specify source home resolution, its forced note creation and reserved target, the migration record, native vault startup/bookmark configuration, and a clear fallback or explicit selection when source home identity cannot be established. Do not silently guess home from title, activation history, or graph topology.

Evidence now includes nine absent type-15 text payloads associated with complete PDFs, external resource references, two icon metadata-length discrepancies, live forgotten thoughts, timestamp strings without timezone suffixes, and sync/deletion history. Decide how to account for each without silently assigning unverified meanings. Determine whether type-15/file-state evidence needs a further controlled export or can be handled explicitly as unclassified/missing source data under the accepted preservation contract.

Use grilling and domain-modeling with the human. Resolve policy from the evidence and accepted trial rather than silently dropping difficult source data.

## Answer

The human confirmed this contract in Q44 on 2026-10-03. It collects the accepted Q23–Q43 choices, with [the resolved vault model](03-vault-model.md) and [Home trial](04-vault-trial.md) as constraints. [Agree acceptance checks and the implementation specification](06-implementation-specification.md) remains the next decision ticket.

**Invocation and target.** Deliver an installable Python package exposing `brz2obsidian inspect SOURCE.brz [--json]` and `brz2obsidian convert SOURCE.brz DESTINATION [--json]`. Inspect is optional, read-only preflight. Convert always performs validation and processes one archive into one new vault. Initial runtime acceptance is native Windows with Python 3.14; the installed research interpreter is 3.14.8. Portable code is desirable, but other runtime/platform support must be demonstrated later. WSL is available development tooling, not a runtime prerequisite.

**Supported source boundary.** Start with the inspected TheBrain 15 exchange-format-5 archives, controlled fixtures, and their verified feature classes/combinations. Do not restrict conversion to exact source fingerprints; use the fingerprints to identify acceptance inputs. Do not promise support for every format-5 archive. Ordinary thoughts, source tags, observed archive-only system records, parent/child and jump relationships, tag assignments, thought-owned verified resource forms, UTF-8 Markdown and observed internal-reference syntax have accepted mappings. The verified ordinary-parent/tag-child hierarchy is included. Unknown content or relationship semantics, other archive formats, rich-note transformations, custom types/fields/events/access semantics, and unverified attachment forms require later investigation. Extra uninterpreted metadata fields and historical records are retained. Naive source date strings stay raw, without an inferred timezone. Larger/new Brains extend coverage when their evidence is available; their research does not block this first specification.

**Publication and failure.** Allow absent or empty destinations only. Refuse a nonempty destination. Build and validate in converter-owned staging, then publish the completed vault. Do not merge into or overwrite an existing vault. On failure, clean only converter-owned staging; report its path if cleanup fails. Refuse corrupt/unreliable source data, invalid live identities/references, missing required content, or unsupported features with an actionable explanation. A failed run produces terminal/optional JSON diagnostics rather than a finished-looking vault. There is no first-version merge, force-overwrite, Home override, or debug-retention flag.

**Thought files and hierarchy.** Use shallow Notes and Attachments folders. Create a thought note for nonblank source thought-note text, a substantive archived file/image, or a supported external resource reference. Empty placeholders, icons, labels, dates, and colors alone do not create files. Apply the same rules to live forgotten thoughts; retain history/tombstones without resurrecting deleted objects. Always select Home first along with content-bearing thoughts. Then greedily select the parent that covers the most currently uncovered accepted hierarchy edges, recomputing after every selection and breaking ties by source ID. Reuse created notes; no global minimum is promised. Remaining empty thoughts are distinct uncreated targets. Each existing endpoint note carries all applicable Parents, Children, and Related lists, omitting empty sections. Preserve hierarchy and multiple parents/cycles through links. Simplify arrows/one-way presentation and retain raw source relationship fields in the record.

**Home and native access.** Resolve Home using the verified setting ID UUIDv5(meta.BrainId, `"20"`) and its thought-UUID Value. Missing/invalid designation refuses conversion with instructions to set Home in TheBrain and re-export. Always create that thought's note at the root as `Home — <readable thought title>.md`, preserving its original heading, label, content, and relationships. Use one assigned target throughout; invent no hierarchy edges. Provide the tested native Home bookmark and startup-file preference. Also configure Notes as the new-note folder, qualified vault links, and source headings rather than filename inline titles. Record the tested Obsidian version. Native Backlinks, Graph, Tags/search, and navigation supply discovery without replacement features or required community plugins.

**Identity and naming.** Reserve targets for both created and uncreated thoughts, including Home, with globally unique thought basenames and supporting filenames reserved. Normalize Unicode to NFC, collapse whitespace, replace a colon with ` - `, brackets with parentheses, unsafe path/link punctuation and controls with spaces, and trim trailing dots/spaces. Prefix Windows device names with `Note - `; use `Untitled` for an empty result. Compare names case-insensitively. Every member of a collision group receives a stable lowercase dashless source-ID suffix, initially eight hex characters and extended four at a time as needed. Resolve natural-title/suffix and truncation collisions deterministically, independent of source/ZIP ordering. Limit the final stem to 120 UTF-16 units without splitting characters or losing Home/identity markers. Validate final absolute paths against a conservative 240-unit bound; give a shorter-destination instruction when they cannot fit. These are converter policies, not universal OS limits. Use original link display text when safely representable, otherwise a readable adapted label; retain exact original titles and every adaptation in the record.

**Content and resources.** Preserve source Markdown and code examples, adapting actual local thought/image references to assigned vault paths rather than changing examples as though they were live links. A valid empty target is intentional; an unresolved live source reference is a failure. Existing inline images stay inline. Other files and external references appear as ordinary Resources links. Fetch no external content. Copy every archived payload once, including decorative icons, under `Attachments/<short-owner-ID>/<readable filename>`, using the stable short-ID scheme and attachment-ID collision suffixes. Apply corresponding resource filename/path safety and length rules. Keep original note bytes, including BOM where present, as `.md.original` backups; icons and backups stay record-accessible without cluttering Resources. Preserve files even when Obsidian cannot preview their type.

**Known warnings.** Continue for the verified absent-payload class: thought-owned type-15 `.txt`, NoteType 0, positive declared length, state 2, absent owner/location bytes, and an intact archived PDF under the same owner. This does not establish the TXT purpose or a particular PDF pairing. Warn in the report/record and add a short filename notice to an existing owner's Resources section; no invented TXT files/links or note created solely for a warning. Other absent-payload patterns, missing ordinary files, missing Markdown note payloads, or missing inline-image bytes stop conversion. For the observed icon length discrepancies, preserve actual CRC-verified bytes and warn in the report/record rather than each owner note.

**Tags and fallback context.** Map source tag assignments to flat native tags on created notes. Replace spaces/slashes/punctuation with hyphens, use `tag-` for numeric-only results and `source-tag` for empty results, and apply stable source-ID suffixes to case-insensitive collisions. Retain authored source-tag content as a normal note. Generate Tag memberships only when needed for absent memberships/otherwise unrepresented source tags. Generate Uncreated targets only when needed for isolated empty ordinary targets or Related pairs whose endpoint files are both absent. Preserve original tag names/memberships in the record. Keep observed system items/relationships JSON-only without guessed navigation meaning.

**Record, report, and root layout.** The root contains Home, `MIGRATION REPORT.md`, `migration-record.json`, and conditional `Tag memberships.md` / `Uncreated targets.md`, alongside Notes, Attachments, and the tested native configuration. The prototype's START HERE remains a trial guide. Put migration instructions and links to conditional listings in the report. Preserve all exported JSON records/fields, source IDs/names, target/resource mappings, original relationship fields, archive fingerprint, adaptations, and structured issues in the migration record. Do not duplicate the whole BRZ. Terminal/report counts account for created/uncreated targets, reasons for creation including hierarchy/Home, retained files, known gaps, and unsupported features. Exit 0 means clean completion, 2 means completion with warnings, and 1 means refusal/failure. Optional JSON provides the result for scripts; failed runs have terminal/JSON diagnostics. Numerical schema details and acceptance assertions will be expressed in the next specification ticket without reopening these accepted policies.

All contract decisions and the shared-understanding confirmation are complete. Acceptance checks, parser/model/writer boundaries, development sequence, and the final implementation-ready specification belong to the next ticket. Production implementation remains outside this wayfinding effort.
