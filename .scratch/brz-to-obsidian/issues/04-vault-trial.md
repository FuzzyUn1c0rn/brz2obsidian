## Question

Does a small vault following the chosen representation preserve the user's content and hierarchical context and feel usable in standard Obsidian?

Use the prototype skill to build a disposable, locally reviewable vault from a representative slice of the real export. Include difficult cases identified by research, with synthetic additions only where the export lacks a case. Keep private content local and link the prototype as an asset.

Draw cases from both exports: differing hierarchy and arrow direction, tags, duplicate titles, invalid filename characters, embedded thought/image references, PDFs, WebP images, and external or absent attachment payloads. Check the selected link form from nested note folders. A controlled source fixture can supply known relationship ground truth.

Include intentional uncreated targets and click-to-create behavior, duplicate names across materialized and uncreated targets, an isolated empty thought, and a relationship between two empty thoughts. Verify that hierarchy survives without generating a note for every empty thought. Evaluate simplified directional links against the user's accepted fidelity boundary rather than requiring TheBrain's visibility behavior.

Apply the selected parent-note exception when neither hierarchy endpoint otherwise has a file; demonstrate both an empty parent/child pair and an empty A→B→C chain where an existing middle note covers both relationships. Show Parents, Children, Related, and Resources sections, native tags, a tag with authored note content, and the small tag/fallback listing for memberships on uncreated targets, isolated targets, and Related pairs between uncreated targets. Preserve readable names and labels, with source metadata in a separate JSON record. Do not expose the observed system relationships as ordinary navigation.

Have the human inspect note readability, relationship navigation, names, attachments, and useful discovery through ordinary Obsidian features. Compare the slice with its source records. A working prototype alone does not resolve this ticket: the human's reaction is required.

Record accepted behavior and any design revisions in the answer. This is a decision aid, not the production converter or the full migration.

## Answer

Adopt the representation from [Choose note identity, relationships, and vault layout](03-vault-model.md), with the accepted Home refinement below. The user reviewed the vault and found it quite good. Native checks show the intended missing links, click-to-create placement, aliases, Backlinks, graph visibility, tags, hierarchy sections, inline images, and PDF Resources links working in standard Obsidian 1.13.7. No community plugin or replacement navigation UI is needed.

Always materialize the designated source Home thought, including when its content is empty. Place `Home — <original thought name>.md` at the vault root beside supporting pages, applying the same readable-name, sanitization, collision, and target-reservation rules as other identities. Preserve its original heading, content, and ordinary relationship sections. Moving its storage location introduces no new hierarchy edges. Every internal link and the migration record must use the one assigned root-level target.

Provide a native bookmark titled Home and select this root-level file as the native default startup file. In the synthetic trial, the bookmark opened Home from Elsewhere; reopening with Elsewhere last active opened Home; the graph visibly identified the Home filename and linked uncreated child. The observed settings are reproduced by `build_home_trial.py`. Their serialized form is evidence for the tested Obsidian version, rather than a documented cross-version configuration guarantee.

[Verified Home source evidence](../research/home-thought.md) establishes the source UUID independently of title, activation history, and topology. The initially generated Review Vault is a bounded slice combining both real Brains; its Home targets were not retroactively changed. The separate Home Checks vault demonstrates the final storage and native behavior. A full conversion must apply the Home exception before final hierarchy coverage and link assignment.

Independent comparison passed for all 21 selected resources, 85 source thought records, and 13 retained source-note texts. Native real-resource checks covered selected PNG/WebP rendering and a PDF first page, not every source note or PDF page. External destinations were not fetched. Naming details, complete content adaptation, deterministic parent selection, output/failure policy, and handling absent or invalid Home designation belong to [Choose the conversion and failure contract](05-conversion-contract.md).
